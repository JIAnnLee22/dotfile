# Plan Mode Extension (优化版)

安全的只读探索模式，用于代码分析和计划制定。

## 功能特性

### UI 改进
- **右上角悬浮窗口** - 计划列表显示在右上角浮动窗口中
- **可滚动** - 支持键盘滚动浏览长计划列表
- **颜色主题** - 使用主题颜色显示不同状态
- **实时状态栏** - 底部显示当前模式和进度

### 流程改进
- **更清晰的模式切换** - 计划模式 → 执行模式 → 正常模式
- **步骤跳过支持** - 使用 `[SKIP:n]` 标记跳过步骤
- **管道命令支持** - 只读组合命令可放行
- **自动完成检测** - 所有步骤完成后自动退出执行模式
- **歧义解析** - 当步骤有多种等效方案时，自动弹出选择对话框

### 进度跟踪
- **进度条** - 可视化显示完成百分比
- **编号一致** - 列表显示、`[DONE:n]`、`[SKIP:n]` 均使用 Plan 中的步骤号

## 快捷键

| 快捷键 | 功能 |
|--------|------|
| `/plan` | 切换计划模式 |
| `/todos` | 显示当前计划进度 |
| `/plans` | 查看已保存的计划文档 |
| `Ctrl+Alt+L` | 切换计划模式 |
| `Ctrl+Alt+P` | 显示/隐藏计划悬浮窗口 |

## 悬浮窗口操作

当计划悬浮窗口打开时：

| 按键 | 功能 |
|------|------|
| `j` / `↓` | 向下滚动 |
| `k` / `↑` | 向上滚动 |
| `PageDown` | 向下翻页 |
| `PageUp` | 向上翻页 |
| `Home` | 跳转到开头 |
| `End` | 跳转到结尾 |
| `q` | 关闭窗口（仅窗口内） |
| `Ctrl+Alt+P` | 关闭窗口 |

## 工作流程

1. `/plan` 启用计划模式
2. 让 AI 分析并输出 `Plan:\n1. [文件路径] 修改描述\n2. ...`
3. 计划会自动显示在右上角悬浮窗口中
4. 计划会自动保存为 Markdown 文档至 `.plans/plan-{sessionId}.md`
5. 按 `Ctrl+Alt+P` 可随时显示/隐藏计划窗口
6. 选择 **执行计划** 开始执行
7. AI 每完成一步输出 `[DONE:n]`，Markdown 文档实时更新
8. 全部完成后自动显示摘要并恢复工具
9. 使用 `/plans` 查看所有已保存的计划文档

## 计划格式

### 普通步骤

```
Plan:
1. [src/auth/login.ts] 在 login 函数中添加参数验证逻辑
2. [src/utils/validators.ts] 创建 validateEmail 辅助函数
3. [tests/auth.test.ts] 添加登录验证的单元测试
```

### 歧义步骤（多方案选择）

当某一步骤有多种等效解决方案时，使用 `[?]` 标记并列出选项：

```
Plan:
1. [src/auth.ts] 实现用户认证 [?] JWT Token | Session-based | OAuth2
2. [src/cache.ts] 添加缓存层 [?] Redis | Memcached | 本地 LRU Cache
3. [src/db.ts] 选择数据库 ORM [?] Prisma | TypeORM | Drizzle
```

- 选项用 `|`、`/` 或 `，` 分隔
- 系统会自动检测歧义步骤并弹出选择对话框
- 用户可以选择：单选方案、组合多个方案、输入自定义方案、或跳过此步骤

## 计划文档保存

每次在计划模式下生成或更新计划时，扩展会自动将计划保存为 Markdown 文档：

- **保存位置**: `{项目目录}/.plans/plan-{sessionId}.md`
- **保存时机**: 计划创建、步骤完成、步骤跳过、计划执行完成
- **文件格式**:
  - 元信息表格（Session ID、工作目录、时间戳、状态）
  - 可视化进度条
  - 带复选框的步骤列表

### 文档示例

```markdown
# 执行计划

| 属性 | 值 |
| --- | --- |
| Session | `abc123` |
| 工作目录 | `/path/to/project` |
| 创建时间 | 2025-06-02T10-30-00 |
| 更新时间 | 2025-06-02T11-15-00 |
| 状态 | **2/3** 完成，1 待执行 |

## 进度

`████████░░░░░░░░░░░░` 67%

## 步骤

- [x] **1.** ✅ [src/auth.ts] 添加参数验证
- [x] **2.** ⏭️ ~~[src/utils.ts] 重构工具函数~~ (已跳过)
- [ ] **3.** [tests/auth.test.ts] 添加单元测试
```

## 歧义解析

当计划中的步骤包含多种等效解决方案时，系统会在计划创建后自动弹出选择对话框。

### 触发条件

步骤文本中包含 `[?]` 标记，且后面列出至少 2 个选项。

### 选择方式

| 选项 | 说明 |
|------|------|
| 方案名称 | 选择该方案 |
| ✏️ 自定义输入 | 输入自定义方案文本 |
| ⏭️ 跳过此步（不执行） | 从计划中移除该步骤 |

### 组合方案

选择一个方案后，系统会询问是否需要添加其他方案。如果选择"是"，可以再选一个方案，最终步骤文本会包含两个方案（用 `+` 连接）。

### 示例

**AI 输出的计划：**
```
Plan:
1. [src/auth.ts] 实现用户认证 [?] JWT Token | Session-based | OAuth2
```

**用户选择后：**
```
1. [src/auth.ts] 实现用户认证：JWT Token + OAuth2
```

## 故障排除

### 计划没有被识别
确保使用 `Plan:` 标题与 `1.` / `2.` 编号列表。

### 命令被阻止
- 确认每段管道均为只读命令
- 避免 `2>/dev/null` 以外的重定向
- 需要修改文件时使用 `/plan` 退出计划模式，或进入执行模式

### 悬浮窗口不显示
- 确保已创建计划（需要有计划步骤才能显示）
- 按 `Ctrl+Alt+P` 尝试切换显示

### 计划文档未保存
- 检查项目目录是否有写入权限
- 确认 `.plans/` 目录已创建
- 使用 `/plans` 查看已保存的文档
