# pi coding agent 工作流优化计划（pi 原生强化版，默认增强 + 计划模式手动开启）

> 目标：围绕 pi 的 **extensions / skills / prompt templates / settings / models**，把 pi coding agent 强化成一个“**能先规划、能稳定搜索、能安全改写、能恢复状态**”的工作流工具。

## 1. 优化原则

- **不重复造轮子**：pi 内置的 `read / write / edit / bash / grep / find / ls` 继续保留，重点做增强与约束。
- **扩展优先**：计划模式、web 搜索、repo 搜索、护栏都通过 extension 落地。
- **配置驱动**：尽量用 settings / prompts / skills / models 管行为，不把规则散在提示词里。
- **默认增强**：基础读写搜索护栏、状态恢复、提示优化默认生效；计划模式仍由用户手动开启。
- **可恢复、可回放**：支持 session start / reload / resume / tree / compaction 场景。
- **全模式可用**：TUI / JSON / RPC / print 都要能用，不依赖单一界面。

## 3. 按优先级的执行顺序

### P0：先把 pi 的工作流骨架跑起来
1. 任务 1：整理 pi 工作流资源与配置入口
2. 任务 2：实现 pi 工作流扩展核心
3. 任务 5：实现计划模式
4. 任务 3：补强本地搜索能力
5. 任务 4：补强写入与风险控制
6. 任务 8：验证、回归与发布

### P1：提升搜索与使用体验
7. 任务 6：增加 Web 搜索工具
8. 任务 7：沉淀 prompt templates / skills

### 顺序说明
- 先把 **pi 的工作流骨架** 搭起来，再补搜索与文档。
- 计划模式要早于 web 搜索和文档，因为它决定主工作流。
- 本地搜索和写入护栏先做，确保执行阶段安全可控。
- web 搜索与模板/skill 放在第二阶段，作为增强能力补齐。

## 4. 最终验收标准

- pi 能围绕“默认增强 + 手动计划模式”完成“理解 → 计划 → 执行 → 验证”闭环。
- 内置工具仍然可用，但被更好的提示、护栏和状态管理强化。
- 本地搜索、写入、web 搜索都能稳定服务于 coding workflow。
- 状态在 reload / resume / tree / compaction 后仍可恢复。
- 整体体验更像一个可控的 pi coding agent，而不是散装工具集合。
